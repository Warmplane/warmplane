What It Actually Solves

Raw MCP integration is powerful, but large agent systems quickly hit practical friction: schema bulk, inconsistent server semantics, duplicated policy logic, and exploding routing complexity. Warmplane packages those concerns into a single managed capability plane that stays small at the protocol edge.

Context Budget Pressure

Agent loops pay repeatedly for tool and prompt metadata. Compact indexes and alias contracts reduce token burn while keeping capability coverage broad.

Operational Fragmentation

Different MCP servers imply different assumptions. The plane normalizes invocation, result envelopes, timeout behavior, and error semantics.

Governance at Runtime

Centralized policy controls allow teams to constrain write actions, separate safe/read paths, and expose only the right capabilities to each agent role.

Core Capabilities

Designed for production agent stacks where tool surfaces must be compact, reliable, and observable.

Unified Facade for Tools, Resources, and Prompts

Build a lightweight contract over many upstream MCP servers. Clients can enumerate compact aliases, request expanded detail only when needed, and call through a normalized interface.

Alias Registry Compact Schemas On-demand Expansion MCP Native Exposure Hybrid Search

Policy Profiles

Role-aware controls for read-only, constrained write, and privileged paths. Enforce profile routing without embedding policy in every agent prompt.

v0.7.1

MCP Spec Parity & SSE Stream

Full compliance with latest MCP specs: POST /v1/completion/complete autocompletion API, real-time GET /v1/resources/updates Server-Sent Events (SSE) stream, and POST /v1/sampling/create_message LLM delegation.

v0.7.0

Pragmatic Rust & Builders

Full adoption of Microsoft's Pragmatic Rust Guidelines (AGENTS.md). Fluent Builder pattern for AppState, SearchFilter, and RequestContext, zero-panic contract, and canonical API docs.

v0.6.0

Idempotency & Deduplication

Pass an idempotency_key or Idempotency-Key header. Concurrent or duplicate requests wait on the active in-flight call and share its result — no double execution upstream.

v0.6.0

Operation Cancellation

Abort any in-flight operation by request ID via POST /v1/operations/:id/cancel or the cancel-operation CLI command. Cancellation propagates immediately.

v0.6.0

Retry Metadata Envelope

Every response includes a structured "retry" field classifying execution safety: safe, unsafe, or idempotent, with execution state for orchestrator-aware retry logic.

v0.5.0

Request Context & Correlation

Envelopes carry structured context fields — operation_id, work_item_id, actor_id, grant_id — propagated from body or HTTP correlation headers (X-Request-ID, X-Actor-ID, …). All span to trace context automatically.

X-Request-ID X-Operation-ID X-Actor-ID X-Grant-ID
v0.4.0

Catalog Versioning & Cache Validation

The capability/resource/prompt catalog is SHA-256 versioned. Clients can use If-None-Match for conditional reads and get 304 Not Modified when nothing has changed. Subscribe to the GET /v1/catalog/events feed to receive incremental change events.

ETag / If-None-Match SHA-256 version /v1/catalog/events

Deterministic Routing

Route each alias to specific upstream targets with stable behavior. Avoid accidental capability drift as your MCP graph evolves.

Reliable Error Envelope

Standardize timeout, retry, and failure responses so agents can recover predictably instead of branching across server-specific error formats.

Enterprise Observability

Emit structured logs for audit trails and export OpenTelemetry traces to existing collectors, with trace IDs that align response envelopes and runtime events.

HTTP Facade & CLI

Full REST API served locally by the daemon, plus a matching CLI for every operation.

HTTP Daemon — /v1 endpoints
# Capabilities
GET  /v1/capabilities
POST /v1/capabilities/search
GET  /v1/capabilities/:id
POST /v1/tools/call

# Resources
GET  /v1/resources
POST /v1/resources/read

# Prompts
GET  /v1/prompts
POST /v1/prompts/get

# Catalog & Operations
GET  /v1/catalog/events
POST /v1/operations/:id/cancel
CLI Facade — example commands
# Discover & search
warmplane list-capabilities
warmplane search-capabilities "triage logs" --limit 5

# Execute with context correlation
warmplane call-capability db.query \
  --params '{"query":"SELECT 1"}' \
  --request-id req-101 \
  --operation-id op-20 \
  --actor-id user-7 \
  --idempotency-key op-20-run-1

# Cancel an in-flight operation
warmplane cancel-operation req-101

# Catalog change events
warmplane list-catalog-events --after evt_3

# Resources & prompts
warmplane read-resource fs.readme
warmplane get-prompt prompt.code-review \
  --arguments '{"code":"fn main() {}"}'

Recent Releases

Warmplane ships focused, production-ready feature increments.

v0.7.1

MCP Specification Parity

POST /v1/completion/complete autocompletion API for prompt and resource arguments. GET /v1/resources/updates real-time Server-Sent Events (SSE) notification stream. POST /v1/sampling/create_message LLM completion delegation reverse proxy endpoint. Synthetic completion_complete tool in stdio MCP server mode. Structured detail payloads in CatalogEventStore.

v0.7.0

Pragmatic Rust Modernization & Builder Patterns

Full adoption of Microsoft's Pragmatic Rust Guidelines (AGENTS.md). Fluent Builder pattern (M-INIT-BUILDER) for core state (AppStateBuilder), search filters (SearchFilterBuilder), and request context (RequestContextBuilder). Enhanced panic safety (M-PANIC-IS-STOP), structured logging (M-LOG-STRUCTURED), canonical API documentation (M-CANONICAL-DOCS), and flexible trait interop (M-IMPL-ASREF).

v0.6.0

Idempotency, Cancellation & Retry Metadata

In-memory idempotency store with broadcast deduplication for concurrent tool calls. Per-request CancellationToken registry with POST /v1/operations/:id/cancel. Structured "retry" envelope field on all execution responses classifying safety (safe, unsafe, idempotent) and state. --idempotency-key CLI flag and cancel-operation subcommand.

v0.5.0

Request Context & Correlation

Structured RequestContext (operation_id, work_item_id, actor_id, grant_id) in all execution envelopes. HTTP header fallback resolution (X-Request-ID, X-Operation-ID, X-Actor-ID, X-Grant-ID). Context propagated to tracing spans and MCP _meta fields. Correlation CLI flags added.

v0.4.0

Catalog Versioning & Cache Validation

SHA-256 catalog version computed from the full capability/resource/prompt index. ETag headers on all catalog reads, If-None-Match conditional request support returning 304 Not Modified. New GET /v1/catalog/events change feed with cursor-based pagination for incremental consumers.

v0.3.0

Hybrid Capability Search

POST /v1/capabilities/search with BM25 lexical scoring, optional ONNX vector embeddings (FastEmbed), tag filters, server-ID filters, and mode selectors. Score-ranked, configurable limit results.

Use Cases

The system is useful wherever multiple agents or teams need controlled access to a growing capability graph without paying linear complexity costs.

Agent Platform Teams

Publish one stable tool plane to all internal agents while swapping and upgrading upstream MCP servers independently.

  • Minimize prompt-level integration details.
  • Ship org-wide policy defaults once.
  • Track capability changes at one control point.

Enterprise Governance

Separate safe discovery and high-impact actions with profile-based controls and explicit alias contracts.

  • Role-specific exposure of tools/resources/prompts.
  • Auditable routing from alias to backend.
  • Constrained write paths for regulated workflows.

LLM Cost and Latency Optimization

Keep the default interface compact and move heavy schema payloads to just-in-time lookups, reducing recurring context load in iterative loops.

  • Smaller baseline tool manifests.
  • Reduced repetitive metadata transfer.
  • Faster first-turn actionability for agents.

Reliable Autonomous Workflows

Idempotent tool calls, in-flight cancellation, and structured retry metadata let orchestrators build resilient multi-step pipelines without duplicate side-effects.

  • Deduplication prevents double-execution on retries.
  • Cancel stale operations from supervisor logic.
  • Retry metadata drives smart backoff decisions.

Why This Matters Now

MCP Is Growing Fast; Integration Debt Grows Faster

As organizations add more MCP servers, direct client integration becomes expensive to maintain. A managed capability plane decouples agent ergonomics from backend sprawl and creates a scalable path for long-lived systems.
